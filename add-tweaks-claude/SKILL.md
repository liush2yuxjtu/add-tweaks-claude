# Add Tweaks Claude Skill

This is the complex, full version of the tweaks pattern. The simple version (one chip that cycles through 3 values in a single file) is `add-tweaks-simple`.

- **Origin:** OpenDesign ([nexu-io/open-design](https://github.com/nexu-io/open-design), [open-design.ai](https://open-design.ai), Apache-2.0). Its Tweaks template is `design-templates/tweaks/` and its design-system format is `design-system-anatomy.md`.
- **Working example:** a Nimbus dashboard demo built with this pattern (multi-file OpenDesign-style project).

## 1. Project structure
```
<design-id>/
  index.html          # generated by build.py (wrap + stage)
  build.py            # merges assets/wrap.html and assets/stage.html
  tokens.css          # design tokens: light and dark, plus the knob variables
  assets/wrap.html    # page shell: viewer toolbar, Tweaks panel, controls
  assets/stage.html   # the design itself (the artboard)
  assets/stage.css    # artboard styles, reading only CSS variables
  assets/tweaks.css   # panel and drawer styles
  assets/tweaks.js    # KNOBS array, setProperty, localStorage, shortcuts
  components.html     # component gallery / preview
  DESIGN.md  SKILL.md  README.md  LICENSE  NOTICE
```
For the served copy, inject `<base href="/<path>/">` into `index.html` so relative assets resolve under a reverse-proxy path prefix.

## 2. Everything is a CSS custom property
- Every visual setting is a variable on `:root`: `--accent`, `--scale`, `--density`, `--motion-mult`, and so on.
- Modes are root attributes, `data-mode="light|dark"` and `data-device="desktop|mobile"`, which switch whole token sets.
- Component CSS never hard-codes colour, size or spacing.
  For example: `padding: calc(16px * var(--density))`, `font-size: calc(14px * var(--scale))`, `transition-duration: calc(200ms * var(--motion-mult))`.

## 3. The KNOBS array (tweaks.js)
```js
const KNOBS = [
  { key:'accent',  id:'tw-accent',  type:'swatch', cssVar:'--accent' },
  { key:'mode',    id:'tw-mode',    type:'seg',    attr:'data-mode' },
  { key:'density', id:'tw-density', type:'seg',    cssVar:'--density',     parse:parseFloat },
  { key:'scale',   id:'tw-scale',   type:'seg',    cssVar:'--scale',       parse:parseFloat },
  { key:'motion',  id:'tw-motion',  type:'seg',    cssVar:'--motion-mult', parse:parseFloat },
  { key:'device',  id:'tw-device',  type:'seg',    attr:'data-device' },
];
const DEFAULTS = { accent:'#c96442', mode:'light', density:1, scale:1, motion:1, device:'desktop' };
```
- Each knob maps one control to one variable or attribute.
- Keep the panel short: about 5 or 6 meaningful knobs.

## 4. Wiring with plain JS
```js
function apply(k, v){
  const r = document.documentElement;
  if (k.cssVar) r.style.setProperty(k.cssVar, k.cssVar==='--accent' ? v : String(v));
  if (k.attr)   r.setAttribute(k.attr, v);
}
// Every control fires change, then apply(), then save().
```
No framework is needed.

## 5. Persistence
- Store the whole state object in `localStorage` under `od-tweaks:<design-id>`.
- Read it with a small inline bridge in `<head>` before first paint, so saved settings apply without a flash.

## 6. Shortcuts
- **T** toggles the panel.
- **R** resets: clear storage and re-apply `DEFAULTS`.
- Ignore both when focus is in an input or textarea.

## 7. Panel layout
- **Desktop:** a fixed right side panel. While it's open, add `tw-open` to the root and give the canvas right padding equal to the panel width, so the panel never covers the artboard.
- **Below 760px:** a bottom drawer with `max-height: 60vh`, scrolling inside, a pinned header, and starting hidden.
- Show and hide it with a CSS class (`tw-hidden`).

## 8. Viewer toolbar
- The slim top bar holds the title, Tweaks, Share and Export.
- The Tweaks button auto-activates only if the panel element exists (`document.getElementById('tw-panel')`).
- On phones, hide the secondary pills.

## 9. Responsive layout and Device mode
- Make the artboard a container (`container-type: inline-size`) and write its layout with `@container` rules. A real phone and the Device=Mobile knob (a 390px framed preview) then share one set of rules.
- Check that there is no horizontal scroll at 390 and 360 pixels wide.

## 10. Design system (DESIGN.md is the source of truth)
DESIGN.md has nine sections:
1. Visual Theme & Atmosphere
2. Color Palette & Roles
3. Typography
4. Layout & Spacing
5. Components
6. Motion & Interaction
7. Iconography & Imagery
8. Voice & Tone
9. Edge Cases & Variations

A new design system is a folder containing `DESIGN.md`, `README.md`, `SKILL.md`, token files (`tokens.css`) and previews (`components.html`, screenshots). Tokens and knob defaults must match DESIGN.md. Update DESIGN.md first, then the code.

## Verify (Playwright)
- No page errors or failed requests.
- Each knob changes its variable and is visible in the design.
- Settings persist after a reload.
- T and R work.
- The drawer works at 390×844.
- No horizontal overflow on phones.
- Desktop and mobile screenshots are captured.
